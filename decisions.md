### ADR-001: Unified Next.js Full-Stack Architecture
- **Context:** The project requires a performant frontend and a backend API for repository analysis.
- **Decision:** Use Next.js 15 App Router as a unified full-stack application.
- **Rationale:** Single deployment unit (Vercel/Docker), shared TypeScript types, elimination of CORS configuration, and zero-latency in-process utility calls.

### ADR-002: Hybrid Vector & Keyword Retrieval Strategy
- **Context:** Developers search code using both conceptual questions ("Where is payment handled?") and exact symbol names ("TAGS.cart", "shopifyFetch").
- **Decision:** Implement hybrid ranking combining 65% cosine similarity on embeddings with 35% keyword and symbol token matching.
- **Rationale:** Pure vector search frequently misses exact variable and function names; pure keyword search fails on conceptual questions. The hybrid approach gives the highest precision.

### ADR-003: Google Gemini 2.0 Flash & text-embedding-004
- **Context:** Need fast, cost-effective LLM reasoning and code embeddings.
- **Decision:** Use Google Gemini 2.0 Flash for text/code reasoning and `text-embedding-004` (768 dimensions) for embeddings.
- **Rationale:** 2.0 Flash provides sub-second reasoning latency, 1M context token capability, low token cost, and native support across all Google developer platforms.

### ADR-004: Language-Aware Code Chunking with Exact Line Numbers
- **Context:** Naive character or token slicing cuts functions in half and loses line number accuracy.
- **Decision:** Parse function and class declarations (using regex/heuristic boundary extractors for TypeScript, JavaScript, Python, Go, Java, Rust) and record exact `startLine` and `endLine` on each chunk.
- **Rationale:** Guarantees that search citations and code viewer highlights always map to syntactically intact code blocks.

### ADR-005: Mermaid.js for Interactive Diagrams
- **Context:** Architectural diagrams should be interactive, editable, and dynamic.
- **Decision:** Render Mermaid graphs client-side using the `mermaid` package.
- **Rationale:** Mermaid definitions are pure text (easily generated by LLMs), render directly into SVG in the browser, and allow clickable node interaction to navigate directly to associated files.

### ADR-006: Security Hardening & Untrusted Repository Code Delimiters
- **Context:** Analyzing public repositories presents prompt injection risks if repository files contain adversarial instructions.
- **Decision:** Treat all repository source code as untrusted text, wrapped in `<untrusted_repository_code>` delimiters with explicit system instructions that code files cannot override agent behavior. Never execute repository code.
- **Rationale:** Guarantees application safety and prevents prompt hijacking.

### ADR-007: Hermetic Font Strategy & Offline-Ready Builds
- **Context:** Default Next.js templates fetch Google Fonts from `fonts.googleapis.com` at build time, failing in air-gapped or sandbox environments.
- **Decision:** Use system font fallbacks (`Inter`, `system-ui`, `-apple-system`, `sans-serif`) in `globals.css` and remove network font downloads.
- **Rationale:** Guarantees 100% reliable, fast, offline-ready production builds on any deployment target.

### ADR-008: Native Node.js Test Runner
- **Context:** Need fast, zero-dependency unit testing for core algorithms.
- **Decision:** Use Node.js 22's built-in `node:test` and `node:assert/strict` with `--experimental-strip-types`.
- **Rationale:** Runs test suites in under 400ms without installing heavy testing dependencies (Jest/Vitest).

### ADR-009: Dual-Mode Vector Indexing with PostgreSQL pgvector
- **Context:** Applications need both low-overhead local demo exploration and scalable persistent vector search across enterprise repositories.
- **Decision:** Implement a dual-mode vector storage layer: embedded in-memory cosine store for zero-config setups, and relational PostgreSQL + `pgvector` with HNSW cosine distance indexing when `DATABASE_URL` is configured (`scripts/init-pgvector.sql`).
- **Rationale:** Gives instant out-of-the-box local developer usability with seamless transition to production multi-tenant vector databases.

### ADR-010: GitHub OAuth Authentication & Token Forwarding
- **Context:** GitHub's public API limits unauthenticated IP requests to 60 calls/hour, risking rate limit exhaustion during large repository ingests.
- **Decision:** Implement a complete GitHub OAuth flow (`/api/auth/github/*`) storing the authenticated access token in secure HTTP-only cookies.
- **Rationale:** Expands rate limits from 60 to 5,000 requests/hour and enables authorized access to private team repositories.

### ADR-011: Fuzzy Command Palette Navigation (Ctrl+K)
- **Context:** Navigating dense repositories with hundreds of files and multiple views creates friction in standard menus.
- **Decision:** Integrate a global modal command palette accessible via `Ctrl+K` / `Cmd+K` that supports fuzzy searching files and pages.
- **Rationale:** Accelerates developer navigation matching VSCode / GitHub native keybindings and mental models.

### ADR-012: Progressive Developer Diagnostics & Route Extractor
- **Context:** Code understanding requires more than basic search: engineers need environment audits, API discovery, and circular dependency checks.
- **Decision:** Provide a dedicated `/utilities` suite analyzing manifest files and ASTs for environment variables (without secret values), API routes (Next.js, Express, Fastify), security vulnerabilities, and circular DAG imports.
- **Rationale:** Delivers actionable, instant insights for audits, PR reviews, and onboarding without third-party static analysis servers.

### ADR-013: Multi-Language Symbol & Import Extraction
- **Context:** Modern GitHub repositories span multiple languages beyond JavaScript/TypeScript, including Python, Go, Rust, and Java.
- **Decision:** Implement dedicated language-aware lexical analyzers in `src/lib/indexing/parser.ts` extracting imports, exports, functions, and classes across TypeScript, JavaScript, Python (`def`/`class`), Go (`func`/`type struct`), Rust (`pub fn`/`pub struct`), and Java (`public class`/methods).
- **Rationale:** Ensures exact symbol indexing, line preservation, and high-precision keyword ranking for polyglot repositories without requiring external tree-sitter C-binding compilers in serverless runtimes.

### ADR-014: Question-Specific Semantic Retrieval for AI Chat
- **Context:** Static chunk slicing (passing the first 5 indexed files) fails when developers ask domain-specific questions about deep modules.
- **Decision:** In `/api/repo/[owner]/[name]/chat`, generate embeddings for the user's latest query, perform hybrid retrieval across the indexed vector store, and pass the top 5 question-relevant code chunks to Gemini.
- **Rationale:** Grounds multi-turn conversational responses directly in the code logic that addresses the developer's specific question.

### ADR-015: Resilient Gemini Model Failover Chain & Diagnostic Route
- **Context:** Google Generative Language API model lifecycles vary (e.g. legacy flash models return HTTP 404, or encounter temporary 503 high-demand spikes). Hardcoding a single model caused silent fallbacks to static offline templates when the user had entered valid API keys.
- **Decision:** 
  1. Implement a prioritized model failover chain in `src/lib/ai/gemini.ts` (`gemini-flash-lite-latest`, `gemini-3.5-flash-lite`, `gemini-3.8-flash`, `gemini-2.5-flash-lite`).
  2. Migrate embedding generation to the Google API v1 `models/gemini-embedding-001` endpoint with automatic fallback.
  3. Ensure `/api/repo/[owner]/[name]/search` feeds query-matched code chunks into Gemini synthesis rather than top-of-store chunks.
  4. Create a dedicated health check route `/api/ai/health` to provide real-time status and diagnostics.
- **Rationale:** Guarantees zero downtime, eliminates silent fallback bugs, and ensures dynamic AI code reasoning runs reliably with verified operational models.
